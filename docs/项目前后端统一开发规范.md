# 项目前后端统一开发规范

更新时间：2026-07-15

## 当前阶段范围

本阶段只建立工作人员身份与权限、知识库配置的可编译架构边界。允许提交接口、数据类型、
路由、OpenAPI 契约和返回 `501 Not Implemented` 的占位 Handler，不实现认证、授权、持久化、
文件解析、发布状态机、向量化或 RAG 检索。

## 后端边界

- `apps/api` 是唯一 Go/Gin API 进程和权威业务状态入口。
- 领域方法放在 `apps/api/internal/modules`，不得依赖 Gin。
- HTTP Handler 只负责路由和协议转换；当前占位阶段不得包含业务规则。
- 数据库、身份源、RAG 和其他外部能力必须通过后续定义的最小接口注入。
- `context.Context` 必须沿调用链传递，不得保存到结构体中。

## 身份与权限

- 身份认证、访问会话和权限判断是不同职责，不得在 Handler 中混合实现。
- 权限判断必须同时考虑 action、机构、服务点、窗口和具体资源作用域。
- 本阶段只定义方法和数据契约，不提供默认允许、管理员后门或演示账号。
- 未实现的身份和权限 API 必须明确返回 `501`，不得返回伪造成功结果。

## 知识库

- 知识导入、人工复核、发布、读取和退役通过明确的方法边界表达。
- 政策材料必须保留来源、版本和人工复核入口；模型结果只能作为候选内容。
- 本阶段不写数据库、不解析文件、不生成向量、不执行 RAG，也不提供演示发布结果。
- 未实现的知识库 API 必须明确返回 `501`，不得返回伪造任务、条目或发布版本。

## 共享契约

- HTTP API 统一位于 `/api/v1`。
- OpenAPI、JSON Schema 和后续生成类型统一放在 `packages/contracts`。
- 前端不得复制 API 类型或绕过 service 层直接散落 HTTP 调用。
- 契约变化必须同步验证后端路由和所有消费者。

## 测试与完成标准

- 使用标准库 `testing` 和 `net/http/httptest`。
- 当前阶段测试必须证明健康检查可用、占位路由存在且稳定返回 `501`。
- 新增 Go 文件必须通过 `gofmt`、`go vet`、单元测试、race test 和 build。
- 不得通过 Fake 成功响应掩盖功能尚未实现的事实。
- 不得提交密钥、真实群众数据、账号、音频、政策正文或供应商响应。
